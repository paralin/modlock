---
title: Abilities and items
description: Swap, train and upgrade abilities, buy items, and redraw the ability bar.
---

These calls swap a hero's abilities and buy items for the hero. The game applies
its own rules and costs to each call. The table spells each call the way
TypeScript and Luau do. Python spells the calls in `snake_case`, and Go
capitalizes them.

| Call                                   | Effect                                                                                                                                                                                                           |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `replaceAbility(index, name, keep?)`   | Puts an ability in a main slot, 0 to 3, including an ultimate placed on another key. The new ability starts untrained, unless you pass `keep` to give it the old one's training, upgrades, cooldown and charges. |
| `trainAbility(slot)`                   | Trains or upgrades whatever the hero holds in a main slot, through the game's path. It charges the unlock or the points, and returns false, spending nothing, when the game refuses.                             |
| `buyItem(item, imbue?, source?)`       | Buys through the game's shop, which applies its rules and charges the souls. Returns false when the shop refuses.                                                                                                |
| `giveItem(item, imbue?)`               | Gives the hero an item, enabled and free. A hero that already owns it keeps its one copy.                                                                                                                        |
| `adjustAbilityPoints(points, unlocks)` | Gives or takes ability points and unlocks. The hero's `abilityPoints` and `abilityUnlocks` then show what is left.                                                                                               |
| `abilityBarPresses(player, handler)`   | Reports each click on a slot's icon or pips as `(player, slot)`.                                                                                                                                                 |
| `abilityDisplay(viewer, rows)`         | Shows the viewer each row's abilities on the Tab screen and the ability bar, in place of the game's.                                                                                                             |
| `setAbility`                           | Changes the first ability with a matching name: its upgrades, charges, timers and [cooldown length](#cooldown-length).                                                                                           |
| `restoreHero`                          | Gives a live hero a saved build, health and cooldowns over a few seconds. Each ability in the target specifies its definition ID and slot, so duplicate abilities are trained independently. |

## Swapped abilities

- The same ability definition can fill several main slots. Each copy is a
  separate ability entity.
- The game trains and upgrades the main abilities by slot. A player holds the
  upgrade key and presses the slot's ability key. Training an untrained
  replacement costs an ability unlock.
- A hero change or `resetHero` restores the hero's own abilities, so apply the
  swap again after either one.
- `imbue` makes the item strengthen whatever ability the hero holds in that
  slot, including an ability that `replaceAbility` put there. If that ability
  does not accept the item, the call fails without spending souls.

## Cooldown length

The `cooldown` option on `setAbility` overrides the duration (in seconds) of
subsequent cooldowns for that ability. For charge-based abilities, it sets the
recharge time between casts. Passing `0` removes the cooldown, and a negative
value restores the game default. An already-running cooldown keeps its end
time; use `cooldownEnd` to adjust it. The override persists for that ability on
that hero until the mod stops or reloads, so reapply it after a hero change or
`replaceAbility`.

| Language   | Three-second cooldown                                                          |
| ---------- | ------------------------------------------------------------------------------ |
| TypeScript | `player.setAbility({ ability: name, cooldown: 3 })`                            |
| Luau       | `player:setAbility({ ability = name, cooldown = 3 })`                          |
| Python     | `player.set_ability(modlock.AbilityOptions(ability=name, cooldown=3))`         |
| Go         | `p.SetAbility(&mod.AbilityOptions{Ability: name, Cooldown: proto.Float32(3)})` |

Go's `Cooldown` is a `*float32`, so an option you do not set stays nil.
`proto.Float32` comes from `google.golang.org/protobuf/proto`.

## Game commands a mod claims

The game's own commands look up the hero's original ability for a slot, so they
miss a swapped one. A mod that swaps abilities intercepts those commands and
handles each one:

| Game command                               | Answer with    |
| ------------------------------------------ | -------------- |
| `upgrade_ability`, `trainorupgradeability` | `trainAbility` |
| `buydependentitem`                         | `buyItem`      |

## The ability bar

Clicking a replaced ability on the game's ability bar does not trigger the
stock command. `abilityBarPresses` reports those clicks so your mod can call
`trainAbility`. Clicks on unreplaced abilities reach your mod through both
paths. Clicks are delivered only while the mod holds the player's HUD, and stop
when the player leaves or the session ends.

The Tab screen and the ability bar draw each hero's standard abilities by slot,
so a replaced ability shows as the one it replaced. `abilityDisplay(viewer,
[{ player, abilities: [{ name, image, upgrades }] }])` draws the rows in the
game's frame and pips, with the ability window over them. The call also draws
the viewer's own row on the bar. Modlock matches each row to a Tab row by the
player's name. When that fails, it matches by the hero's name, which is what a
bot's row shows. When the viewer leaves or the session ends, the game's own
display comes back.

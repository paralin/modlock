## In the sandbox

On macOS, or on any computer without Deadlock, `modlock dev` runs your mod in
the sandbox. The sandbox has the same runtime and event limits as a server, and
one stand-in player without a hero. It does not throttle slow frames like a
live server, so [measure performance](/performance/measure) in-game.

When you type `/hello` in the terminal and press Enter, the sandbox sends it as
that player's chat. The terminal shows your mod's log and everything the mod
sends to players. Calls that need the game, such as reading a hero's position,
return nothing.

The preview page at `http://127.0.0.1:4322/` draws the screens your mod shows
that player, the way the game would. On the page you can press the player's
buttons, send chat commands and pick a screenshot of the game as the backdrop.
The page also shows a build in progress, a failed build's errors, and why a mod
stopped.

| Flag             | Does                                                                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--sandbox`      | Uses the sandbox even where the game is installed.                                                                                                           |
| `--preview-port` | Serves the page on another port, or turns it off with 0. When another program holds the port, the page takes a free one and the terminal prints its address. |

In a Python mod, the sandbox also runs each terminal line that starts with `>`
as Python inside the running mod, as
[Python](/languages/python#run-a-line-in-the-running-mod) explains.

<Only lang="go">
  You can test game rules that do not call into the game with plain `go test`,
  as the [`race`](https://github.com/paralin/modlock/tree/master/examples/race)
  example does.
</Only>

## In the game

To test a whole round in the game, build the test into the mod. When you start
it with `modlock play -- probe`, the mod seats bots with `addBot` and plays the
round. Then it checks the outcome, logs PASS or FAIL and quits with
`serverCommand('quit')`, as
[`examples/arena`](https://github.com/paralin/modlock/blob/master/examples/arena/probe.ts)
does.

In TypeScript, `ProbeRun` tracks multi-step integration probes. Call `tick` each
frame with the current step label and a predicate returning `true` to advance,
an error string to fail, or `false` to keep waiting. `ProbeRun` logs each step
transition once, fails on timeout, and logs `<name> probe PASS` or `FAIL`
before quitting:

```ts
const run = new ProbeRun('Duel', 120)
onFrame((frame) => {
  run.tick(frame.timeSeconds, 'two fighters', () => fighters() >= 2)
})
```

A probe that seats a full server of bots also shows whether the mod keeps
within its [frame budget](/performance/frame-budget).

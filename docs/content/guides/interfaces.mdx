Each language has an interface library: JSX in TypeScript, `@modlock/ui` in
Luau, `modlock.ui` in Python and `mod/ui` in Go. Each library has a HUD kit
(`hud`) and style tokens (`theme`). This screen asks the player to click. The mod frees the
cursor and blocks the buttons a click would fire, and `closePicks` releases them:

<Samples>

```tsx
import { Buttons, freeCursor, hide, type Player, show } from 'modlock'

function openPicks(player: Player): void {
  show(
    player,
    <panel style={{ flow: 'down', padding: 24, background: '#101820e0' }}>
      <label style={{ fontSize: 28 }}>Pick a hero</label>
      <button onPress={closePicks}>Ready</button>
    </panel>,
  )
  freeCursor(player, true)
  player.blockInput(Buttons.attack | Buttons.altFire | Buttons.melee)
}

function closePicks(player: Player): void {
  player.blockInput(0n)
  hide(player)
}
```

```luau
local modlock = require("@modlock")
local ui = require("@modlock/ui")

local function closePicks(player: modlock.Player)
	player:blockInput(0)
	ui.hide(player)
end

local function openPicks(player: modlock.Player)
	ui.show(player, ui.panel {
		style = { flow = "down", padding = 24, background = "#101820e0" },
		ui.label { style = { fontSize = 28 }, "Pick a hero" },
		ui.button { onPress = closePicks, "Ready" },
	})
	ui.freeCursor(player, true)
	-- Each button is a bit, so their sum blocks all of them.
	player:blockInput(modlock.Buttons.attack + modlock.Buttons.altFire + modlock.Buttons.melee)
end
```

## Calls

Luau spells each call as TypeScript does, Python in `snake_case`, and Go
capitalizes it. In Go, `toast` with seconds is `ToastFor`, and `uiSound` is
`Sound`.

| Call                                          | Effect                                                                                                                                                                                                                               |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `show(player, element)`, `hide(player)`       | Show a player an interface written in JSX, or remove it.                                                                                                                                                                             |
| `toast(player, text, seconds?)`               | Show a player a short notice that fades.                                                                                                                                                                                             |
| `uiSound(player, sound, { seconds? })`        | Play a game sound event to one player once, hero or not; `seconds` stops it early. A run of sounds, such as a wheel's ticks, is a timeline.                                                                                          |
| `playTimeline(player, id, { clock?, steps })` | Run a timed presentation: each step, at seconds from the start, gives the elements of its `measure` a `class` and `style` and plays its `sound`. Playing it again starts it over; `clock: 'game'` holds it while the game is paused. |
| `cancelTimeline(player, id)`                  | Stop a timeline, taking back its looks and its sounds still to come.                                                                                                                                                                 |
| `hideHud(player, parts)`                      | Hide parts of the game's HUD, such as `'topBar'`, `'minimap'`, `'minimapPlayers'`, `'inventory'`, `'crosshair'`, `'castFailed'`, `'eventIndicators'`, `'statusIndicators'` or `'all'`; `[]` shows them again.                        |
| `hideHudForAll(parts)`                        | Hide parts of the game's HUD from every player, those who join later too. TypeScript only.                                                                                                                                           |
| `showChatLines(options?)`                     | Show chat lines as subtitles above the ability bar, with the speaker's portrait and name. TypeScript only.                                                                                                                           |
| `showSpeakers(options?)`                      | Show who each player hears on voice chat, as portraits and names at the left edge. TypeScript only.                                                                                                                                  |
| `freeCursor(player, free)`                    | Show the mouse cursor without Tab, so the player can click; `false` gives the mouse back to aiming.                                                                                                                                  |
| `abilityBarPresses(player, onPress?)`         | Take clicks on the game's ability bar by slot; see [Abilities](/guides/abilities).                                                                                                                                                   |
| `followAction(player, action, onPhase?)`      | Follow a game action, such as `'scoreboard'`, on whichever key the player bound it to: `'pressed'`, then `'released'` or `'cancelled'`; see [Follow a game action](#follow-a-game-action).                                           |
| `followOverlay(player, onChange?)`            | Hear which stock overlay holds the player's input, such as `'chat'`, `'shop'` or `'escapeMenu'`, and `'none'` once the game has it back; see [Follow the stock overlays](#follow-the-stock-overlays).                                |
| `followPlacement(player, onPlace?)`           | Hear the screen's size, the HUD's frame and the box of each element named with `measure`; see [Place by the screen](#place-by-the-screen).                                                                                           |
| `inHudFrame(player, on)`                      | Draw the interface in the HUD's frame, the middle 16:9 of a wider screen whose player keeps the HUD there.                                                                                                                           |
| `abilityDisplay(viewer, rows?)`               | Show players' replaced abilities on Tab and the ability bar; no rows brings back the game's own.                                                                                                                                     |
| `cursorFree(player)`                          | Read whether the player's cursor is up now, however it got there.                                                                                                                                                                    |
| `items`, `item(name)`                         | The shop's items: id, slot, tier, active, imbue and icon. TypeScript only.                                                                                                                                                           |
| `player.screenEffect(effect, timing?)`        | Play `'black'`, `'killed'`, `'blinded'`, `'darkness'` or `'matchIntro'` over the view.                                                                                                                                               |
| `player.clearScreenEffect(effect)`            | End that effect, such as lifting a black screen at a round's start.                                                                                                                                                                  |
| `route(player, name, value)`                  | Hand every layout of the mod `value` under `name`; see [Layouts](/guides/layouts).                                                                                                                                                   |

## The cursor

While the cursor is up, the game still shoots, turns and moves the hero. The mod
blocks those buttons itself, and releases them in the same call that hides the
screen. `hide` gives the mouse back to aiming.

The player can also put the cursor away with the game's own keys. The cursor
then stays away while the screen changes, until the next
`freeCursor(player, true)` shows it again. `cursorFree(player)` reports whether
the cursor is up, and nothing while the player has no hero. A mod that wants the
cursor back calls `freeCursor` again when `cursorFree` reports false, on a press
or a timer.

## Follow a game action

`followAction` tells the mod when the player uses one of the game's own bound
actions, so a mod can answer Tab without a key of its own. Each press reaches
the mod once as `'pressed'` and once more as `'released'`, or as `'cancelled'`
when chat, the shop, a popup or the escape menu takes the player's input
before they let go. A press made while one of those is open reports nothing.
The game still does what the action does, so the scoreboard still shows. A
mod reads the action whatever key the player bound it to.

```ts
followAction(player, 'scoreboard', (player, phase) => {
  if (phase === 'pressed') showStats(player)
  else hideStats(player)
})
```

## Follow the stock overlays

`followOverlay` tells the mod which of the game's own overlays holds the
player's input, so a mod can pause its own timer, hide a prompt or end a drag
while the player types in chat or browses the shop. The handler hears the
current overlay at once, then each change, and `'none'` once the game has the
input back. The overlays are `'chat'`, `'shop'`, `'builds'`, `'itemDraft'`,
`'popup'` and `'escapeMenu'`, and when several are open it names the first in
that order. The renderer reads them ten times a second, and only while some
mod follows them.

```ts
followOverlay(player, (player, overlay) => {
  if (overlay === 'none') resumeRound(player)
  else pauseRound(player)
})
```

## Place by the screen

A root takes its place with its own `style`: `horizontalAlign` and
`verticalAlign` name the edge or corner and `margin` the gap, in layout units, which the game scales so the screen is
1080 units tall at any resolution. On a 21:9 screen the player can keep the
game's HUD in the middle 16:9, and `inHudFrame(player, true)` draws the
interface in that same frame, so a panel aligned to its top right corner
lines up with the game's own HUD on every screen:

```ts
inHudFrame(player, true)
show(
  player,
  <panel
    style={{ horizontalAlign: 'right', verticalAlign: 'top', margin: [24, 24, 0, 0] }}
  >
    <label>Round 2</label>
  </panel>,
)
```

A mod that places something the interface does not draw, such as a world
preview or a camera's frame, reads where the screen put things with
`followPlacement`. Its handler hears the screen's size, the HUD's frame and
the box of each element whose `measure` names it, all in layout units from
the screen's top left: the whole placement first, then again whenever any of
it moves, such as after the player changes resolution. The renderer reads the
layout after each draw and four times a second, and only while some mod
follows.

```ts
followPlacement(player, (player, { screen, hud, measured }) => {
  const box = measured.get('preview')
  if (box) aimPreview(player, box.x / screen.width, box.y / screen.height)
})
```

## Replace the top bar

The game's top bar shows each player's portrait, their chat line under it for a
few seconds, and a mark while their voice plays. A mode that hides the top bar
for its own score keeps the voices with `showSpeakers` and the chat lines with
`showChatLines`, which draws them as subtitles: centred low on
the screen a little above the ability bar, each the speaker's small portrait,
their name in their team's color and the line itself on a slim, translucent
band. The lines give way while the player has the game's chat box open, since
the box then shows the history itself. Call both when the mod loads:

```ts
import { hideHudForAll, showChatLines, showSpeakers } from 'modlock'

hideHudForAll(['topBar'])
showChatLines()
showSpeakers()
```

At most four lines show, newest at the bottom and older ones dimmer, and a
speaker's next line replaces their last. A long line wraps. A team line reads
only to the speaker's team and a line to all reads to everyone. A command such
as `/help` is not shown. `{ seconds }` sets how long a line stays, 6 unless set,
`{ lines }` how many show, and `{ bottom }` moves the lane up from the bottom
edge. `{ scale }` sizes each line, its text, portrait, band and spacing
together, so `0.8` draws the text at 13 pixels on a band at most 448 wide, and
`{ portraits: false }` leaves the portraits out. A mode whose sides are not the game's teams passes
`{ speaker(speaker, viewer) }`, which returns the name's `color`, the portrait's
`hero` (0 hides it), a `note` after the name and whether the speaker is `out`.

`showSpeakers` stacks a row at the left edge for each player the viewer hears:
the speaker's portrait in a green ring, their name and the voice icon. A row
stays a moment after the voice stops, so a pause between words does not blink
it, and rows keep slot order, so the stack does not reorder as people talk over
each other. The player's game shows and hides the rows by the voice marks it
keeps on the hidden top bar, so voices starting and stopping cost the mod
nothing. `{ scale }` sizes the rows, and `{ speaker }` takes the same function
as `showChatLines`, so a player looks the same in both.

The library draws the lines and the stack as layers of their own over whatever interface the
mod shows each player, as it draws toasts: a line arriving or leaving redraws
only the lines, and the mod does not redraw for them. A player's own `hideHud`
list adds to the parts hidden from everyone, and `hide` leaves those parts
hidden.

## Style it

Style `panel`, `label`, `image`, `hero`, `button` and `layout` with:

| Group  | Properties                                                                                                                                                                                                                                                                                                                                                                         |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Layout | `width`, `height`, `minWidth`, `maxWidth`, `minHeight`, `maxHeight`, `x`, `y`, `zIndex`, `margin`, `padding`, `horizontalAlign`, `verticalAlign`, `flow` (`'down'`, `'right'`, `'downWrap'`, `'rightWrap'`), `overflow`, `overflowX`, `overflowY` (`'squish'`, `'clip'`, `'scroll'`, `'show'`)                                                                                     |
| Paint  | `background`, `gradient` (`{ shape, colors, at }`), `borderRadius`, `borderWidth`, `borderColor`, `boxShadow`, `opacity`, `tint`, `saturation`, `brightness`, `contrast`, `blur`, `clip` (a box `{ rect: [top, right, bottom, left] }` in percents, or a slice `{ center?, start, sweep }` in degrees, such as a cooldown ring; it does not ease)                                  |
| Text   | `color`, `fontSize`, `face` (the game's `body`, `block` or `serif`), `bold`, `weight`, `italic`, `uppercase`, `letterSpacing`, `lineHeight`, `textAlign`, `noWrap`, `textOverflow` (`'ellipsis'`, `'shrink'`, `'clip'`), `decoration` (`'underline'`, `'strike'`), `shadow`, `textShadow`                                                                                          |

## Inputs

Each input hands each change to `onChange(player, value)`:

| Input        | Props                               | Value                                    |
| ------------ | ----------------------------------- | ---------------------------------------- |
| `<entry>`    | `value`, `placeholder`, `maxLength` | Text, cut to `maxLength` characters.     |
| `<slider>`   | `value`, `min`, `max`, `step`       | A number, clamped to the range and step. |
| `<range>`    | `handles`, `min`, `max`, `step`     | Every handle's number, in order.         |
| `<toggle>`   | `on`, label as children             | On or off.                               |
| `<dropdown>` | `options`, `selected`               | The chosen option's index.               |

The host drops a change to a disabled input or one the player no longer sees.
The player's edit shows until your mod draws a new value, so store the value
your handler receives and draw it back.

An entry or slider sends a run of edits once, a tenth of a second after the
last. It sends at once when it loses the keyboard or when the player presses a
button in the same interface, so a Save or Apply button's `onPress` runs after
every `onChange` for the values the player sees.

A range is a track with one to eight named handles, such as a minimum, a
favored value and a maximum:

```tsx
<range
  handles={[
    { name: 'min', value: 0.2 },
    { name: 'favored', value: 0.5 },
    { name: 'max', value: 0.8 },
  ]}
  step={0.05}
  onChange={(player, [min, favored, max]) => save(player, min, favored, max)}
  onHold={(player, handle, phase) => preview(player, handle, phase)}
/>
```

The player drags one handle at a time, and it stops at its neighbors. It
follows the pointer past the track's ends, so the player can push it to the
end without aiming. `onChange` runs once, with every value, when the player
lets go. `onHold` hears each grab, release and cancellation by the handle's
name. A stock overlay, the menu's closing or disabling the range cancels the
drag and puts the handles where your mod last drew them. While the player holds
a handle, a redraw leaves the handles where the player has them. Changing the
handles' names draws a new range.

The range is one stop in the game's keyboard and controller navigation. While
it has the focus, left and right step its active handle by `step`, or a
twentieth of the track without one, stopping at its neighbors, and Enter or
the controller's confirm makes the next handle active, which shows outlined.
Each step runs `onChange` with every value at once, and `onHold` hears it as a
release. In Python the element is `range_`, and in Go `ui.Range`.

In TypeScript, a form can direct the keyboard. `focusOrder` on a button or
input sets its place in the game's keyboard and controller navigation, lowest
first. `initialFocus` gives a control the keyboard when its menu opens. A
button with `submits` is pressed when the player presses Enter in an entry of
the same menu, after the entry's edit, so the player can type a name and press
Enter to save. Escape still closes the menu without calling the mod.

## Long lists

A list scrolls more rows than an interface may hold as nodes, such as a
leaderboard of every player. Each row is drawn from one template, whose text,
images and variables name the row's fields as `{field}`:

```tsx
<list
  style={{ height: 400 }}
  rowHeight={32}
  row={<label>{'{name}: {score}'}</label>}
  rows={players.map((p) => ({
    key: p.id,
    rank: -p.score,
    fields: { name: p.name, score: String(p.score) },
  }))}
/>
```

The rows show in order of `rank`, then `sort`, then `key`, and each row's key
names it while the rows change. The host holds every row and sends the
player's game only the rows near what the list shows, and the game builds
panels only for the rows in view, so a list of ten thousand rows costs the
player what a list of a hundred does. The player scrolls with the wheel. A
draw that passes the same `rows` array as the last draw sends nothing and
costs nothing, however long the list, so keep the array while its rows stay
the same and pass a new one to change them. A draw with a new array compares
every row with the rows the player holds and sends only the rows added,
changed and removed.

A row's height is fixed by `rowHeight`, from 1 to 1000 pixels, and the list's
own `height` is how much of it shows. The template is a panel, label or image
holding at most fifteen more, with no buttons or inputs. A row has at most
sixteen fields. The host takes at most 20,000 rows in a list, and 2 MiB of rows
across a player's interface. In Python the element is `list_`, and in Go
`ui.List`.

The player focuses a row with the arrow keys or the controller, and chooses
it with Enter, the controller's confirm button or a click. A choice runs
`onChange` with the row's key, and the mod draws that key back as `selected`,
the same way an input draws back its value:

```tsx
<list
  rowHeight={32}
  row={<label>{'{name}'}</label>}
  rows={rows}
  selected={chosen}
  focusStyle={{ background: '#ffffff22' }}
  selectedStyle={{ color: '#ffd24a' }}
  onChange={(player, key) => {
    chosen = key
  }}
/>
```

`focusStyle` is drawn over a row's style while the player focuses it, and
`selectedStyle` while it is selected. The focus belongs to the player's game,
which keeps it on its row as rows are added, removed or reordered above it.
When the focused row leaves the list, the focus moves to the row that took its
place. A selected key that the list no longer holds shows nothing selected.

## Local menus and portable text

Use a TypeScript `<menu>` when settings or a result should give the player a
cursor and then return it without a server round trip. `mode="toggle"` opens
and closes on successive presses of the game's scoreboard binding (Tab by
default). `mode="hold"` opens while that binding is held. The default,
`mode="manual"`, opens from its optional `openLabel` button when the player
already has a cursor, or when a positive `openRequest` number increases. Keep
the menu's JSX key stable and advance that number once per new result, not on
ordinary redraws. A request that arrives while the shop, chat or another menu
holds the cursor waits, and the menu opens once they close, unless you have
stopped drawing it by then. One request waits at a time. Give a menu a
`priority` to order your own menus: a request waits while your open menu has a
higher priority, and otherwise replaces it, so an alert at priority 2 can
interrupt a warning at priority 1 and the warning can wait behind the alert.
Another mod's open menu always keeps your request waiting, and the stock
interface always wins. Put a `<menuClose>` inside the menu for an explicit
dismiss button. Escape, stock overlays taking focus, and loss of the surface dismiss it
locally. A dismissal never calls the mod.

Use `<documentOutput text={text} />` for a plain-text export the player can
select and copy with the game's usual controls. `<documentInput>` gives the
player a multiline draft. It sends nothing while they type or paste, or when
they press Enter in the draft. The form's button, named by `submitLabel`
(`"Submit"` by default), sends the whole draft to `onSubmit(player, text)`.
Use `placeholder` to prompt for the expected format, and `disabled` to suspend
editing and submission. Each player can have one document input and one
document output per mod. Both hold at most 262,144 UTF-8 bytes (256 KiB); the
ordinary `<entry>` keeps its short limit.

Each submission ends in exactly one callback. A whole document reaches
`onSubmit(player, text)`. Any other end reaches `onFailure(player, failure)`
with its reason: `tooLarge` for a draft past the limit, `expired` for a
transfer that did not finish in time, `cancelled` when the player closed the
menu while it sent, and `malformed` for frames that were missing or not text.
A transfer has 20 seconds plus its sending time, about one second for each
14,400 bytes, so a full-size document has about 38 seconds. Show the outcome
from these callbacks, since the renderer knows only that it sent the draft.
A mod that replaces or removes the form ends its submission with no callback.
Validate the document in the mod, and ask for confirmation before replacing a
saved record. The host checks that the sending player still owns the current
form, not how the player entered the text. Neither control gives a mod
clipboard access.

Try the built-in controls with `modlock dev examples/interface-session`.
The example echoes disposable text and keeps no saves.

## The HUD kit

The HUD kit draws components in the look of the game's own HUD. This sample
draws a round's score across the top of the screen:

<Samples>

```tsx
import { Score, show, TopStrip } from 'modlock'

show(
  player,
  <TopStrip heading="Round 2">
    <Score points={[1, 0]} />
  </TopStrip>,
)
```

```luau
local hud = require("@modlock/hud")

ui.show(player, hud.TopStrip { heading = "Round 2", hud.Score { points = { 1, 0 } } })
```

```python
from modlock.hud import score, top_strip

show(player, top_strip(heading="Round 2")[score(points=(1, 0))])
```

```go
// import "github.com/paralin/modlock/mod/hud"
ui.Show(p, hud.TopStrip{Heading: "Round 2", Children: hud.Score{Points: [2]int{1, 0}}})
```

</Samples>

| Component               | Draws                                                                        |
| ----------------------- | ---------------------------------------------------------------------------- |
| `<Text role>`           | Text in one of the kit's type roles.                                         |
| `<Plate>`, `<Pill>`     | A dark plate under text, so the text reads over a bright sky.                |
| `<Pips>`                | A count, as the round counter shows it.                                      |
| `<Tag>`                 | A status label.                                                              |
| `<Banner>`              | An announcement of a moment.                                                 |
| `<TopStrip>`, `<Score>` | The top of the screen, with a score in it.                                   |
| `<Roster>`              | The players down the top right corner, with hero portraits.                  |
| `<Action kind>`         | A button in the game's menu look, with its hover, sounds and disabled state. |
| `<Meter value>`         | A bar that eases to each new value.                                          |

`theme` contains the tokens for a mod's own panels, such as `theme.tones` and
`theme.sizes`, and each entry in `heroes` has its small `portrait`.
[Layouts](/guides/layouts) describes layouts from the mod's content, style
sheets and how the game draws an interface.

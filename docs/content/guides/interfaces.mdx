description: Draw a HUD, a menu or a notice on a player's screen.

You draw an interface with your language's interface library: JSX in
TypeScript, `@modlock/ui` in Luau, `modlock.ui` in Python and `mod/ui` in Go.
Each library also has a HUD kit, `hud`, and a set of style tokens, `theme`.

The sample below shows a player a screen with one button. `openPicks` draws the
screen, shows the mouse cursor so the player can click, and blocks the fire
buttons so that a click does not shoot. `closePicks` releases the buttons and
removes the screen:

<Samples>

```tsx
import { Buttons, freeCursor, hide, type Player, show } from 'modlock'

function openPicks(player: Player): void {
  show(
    player,
    <panel style={{ flow: 'down', padding: 24, background: '#101820e0' }}>
      <label style={{ fontSize: 28 }}>Pick a hero</label>
      <button onPress={closePicks}>Ready</button>
    </panel>,
  )
  freeCursor(player, true)
  player.blockInput(Buttons.attack | Buttons.altFire | Buttons.melee)
}

function closePicks(player: Player): void {
  player.blockInput(0n)
  hide(player)
}
```

```luau
local modlock = require("@modlock")
local ui = require("@modlock/ui")

local function closePicks(player: modlock.Player)
	player:blockInput(0)
	ui.hide(player)
end

local function openPicks(player: modlock.Player)
	ui.show(player, ui.panel {
		style = { flow = "down", padding = 24, background = "#101820e0" },
		ui.label { style = { fontSize = 28 }, "Pick a hero" },
		ui.button { onPress = closePicks, "Ready" },
	})
	ui.freeCursor(player, true)
	-- Each button is a bit, so their sum blocks all of them.
	player:blockInput(modlock.Buttons.attack + modlock.Buttons.altFire + modlock.Buttons.melee)
end
```

```python

```

## Calls

The table gives each call's TypeScript name. Luau uses the same names, Python
writes them in `snake_case`, and Go capitalizes them. Two Go names differ: a
`toast` with seconds is `ToastFor`, and `uiSound` is `Sound`.

| Call                                          | Effect                                                                                                                                                                                                                               |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `show(player, element)`, `hide(player)`       | Show a player an interface written in JSX, or remove it.                                                                                                                                                                             |
| `toast(player, text, seconds?)`               | Show a player a short notice that fades away.                                                                                                                                                                                             |
| `uiSound(player, sound, { seconds? })`        | Play a game sound event once to one player, whether or not they have a hero. `seconds` cuts the sound short. For a run of sounds, such as a wheel's ticks, use a timeline.                                                                                          |
| `playTimeline(player, id, { clock?, steps })` | Run a timed presentation. Each step starts `at` a number of seconds from the start, gives the elements its `measure` picks a `class` and a `style`, and plays its `sound`. Playing a timeline again starts it over. With `clock: 'game'` it waits while the game is paused. |
| `cancelTimeline(player, id)`                  | Stop a timeline. Its elements lose the looks it gave them, and its sounds still to come do not play.                                                                                                                                                                 |
| `hideHud(player, parts)`                      | Hide parts of the game's HUD, such as `'topBar'`, `'minimap'`, `'minimapPlayers'`, `'inventory'`, `'crosshair'`, `'castFailed'`, `'eventIndicators'`, `'statusIndicators'` or `'all'`. Passing `[]` shows them again.                        |
| `hideHudForAll(parts)`                        | Hide parts of the game's HUD from every player, including players who join later. TypeScript only.                                                                                                                                           |
| `showChatLines(options?)`                     | Show chat lines as subtitles above the ability bar, with the speaker's portrait and name. TypeScript only.                                                                                                                           |
| `showSpeakers(options?)`                      | Show who each player hears on voice chat, as portraits and names at the left edge. TypeScript only.                                                                                                                                  |
| `freeCursor(player, free)`                    | Show the mouse cursor, so the player can click without holding Tab. `false` gives the mouse back to aiming. See [The cursor](#the-cursor).                                                                                                                                  |
| `abilityBarPresses(player, onPress?)`         | Hear clicks on the game's ability bar, by slot. See [Abilities](/guides/abilities).                                                                                                                                                   |
| `followAction(player, action, onPhase?)`      | Hear each use of a game action, such as `'scoreboard'`, on whichever key the player bound it to: `'pressed'`, then `'released'` or `'cancelled'`. See [Follow a game action](#follow-a-game-action).                                           |
| `followOverlay(player, onChange?)`            | Hear which of the game's overlays has the player's input, such as `'chat'`, `'shop'` or `'escapeMenu'`, and `'none'` once the game has the input back. See [Follow the stock overlays](#follow-the-stock-overlays).                                |
| `followPlacement(player, onPlace?)`           | Hear the screen's size, the HUD's frame and the box of each element you named with `measure`. See [Place by the screen](#place-by-the-screen).                                                                                           |
| `inHudFrame(player, on)`                      | Draw the interface inside the HUD's frame. On a screen wider than 16:9, a player can keep the HUD in the middle 16:9, and the frame is that middle part.                                                                                                                           |
| `abilityDisplay(viewer, rows?)`               | Show a viewer the abilities you list for each player on the Tab screen and the viewer's ability bar, where the game would show a replaced ability as the one it replaced. Calling it with no rows brings back the game's own.                                                                                                                                     |
| `cursorFree(player)`                          | Read whether the player's cursor is up now, whether your mod or the player put it there.                                                                                                                                                                    |
| `items`, `item(name)`                         | The shop's items, each with its id, slot, tier, active, imbue and icon. TypeScript only.                                                                                                                                                           |
| `player.screenEffect(effect, timing?)`        | Play `'black'`, `'killed'`, `'blinded'`, `'darkness'` or `'matchIntro'` over the player's view.                                                                                                                                               |
| `player.clearScreenEffect(effect)`            | End an effect, such as lifting a black screen when a round starts.                                                                                                                                                                  |
| `route(player, name, value)`                  | Pass `value` under `name` to every layout of the mod. See [Layouts](/guides/layouts).                                                                                                                                                   |

## The cursor

`freeCursor(player, true)` shows the player's mouse cursor, so they can click
your panels without holding Tab. While the cursor is up, a click on one of your
mod's panels goes to that panel, and the hero does not shoot. A click anywhere
else on the screen fires the weapon as usual. Moving the mouse still turns the
camera, and the movement keys still move the hero.

So when a screen must never fire the weapon, block the fire buttons with
`player.blockInput` as you show it, as `openPicks` does above. Then release them
in the same function that hides the screen, as `closePicks` does, so the player
can shoot again as soon as the screen is gone. `hide(player)` and
`freeCursor(player, false)` both put the cursor away and give the mouse back to
aiming.

The player can also put the cursor away with the game's own keys. It then stays
away, even when your mod draws a new screen, until your mod calls
`freeCursor(player, true)` again. `cursorFree(player)` tells you whether the
cursor is up now, whether your mod or the player put it there. It returns no
value while the player has no hero, because the game keeps the cursor's state
on the hero. To bring the cursor back, check `cursorFree` on a press or a timer,
and call `freeCursor(player, true)` when it returns false.

## Follow a game action

`followAction` calls your handler when the player uses one of the game's own
actions, on whatever key they bound it to. So your mod can answer Tab, the
scoreboard action, without asking the player to learn a key of its own. Each
press reaches the handler twice: once as `'pressed'`, and once more as
`'released'` when the player lets go. If chat, the shop, a popup or the escape
menu takes the player's input before they let go, the second call is
`'cancelled'` instead. A press made while one of those overlays is open does
not reach the handler at all. The game still does what the action does, so the
scoreboard still shows.

```ts
followAction(player, 'scoreboard', (player, phase) => {
  if (phase === 'pressed') showStats(player)
  else hideStats(player)
})
```

## Follow the stock overlays

`followOverlay` tells your mod which of the game's own overlays has the
player's input. You can use it to pause a timer, hide a prompt or end a drag
while the player types in chat or browses the shop. The handler hears the
current overlay as soon as you call `followOverlay`, then each change, and
`'none'` once the game has the input back. The overlays are `'chat'`, `'shop'`,
`'builds'`, `'itemDraft'`, `'popup'` and `'escapeMenu'`. When several are open,
the handler hears the one that comes first in that list. The renderer reads the
overlays ten times a second, and only while some mod follows them.

```ts
followOverlay(player, (player, overlay) => {
  if (overlay === 'none') resumeRound(player)
  else pauseRound(player)
})
```

## Place by the screen

You place a root element with its own `style`. `horizontalAlign` and
`verticalAlign` pick the edge or corner it sits against, and `margin` sets the
gap from that edge. Sizes are in layout units, and the game scales them so the
screen is 1080 units tall at any resolution.

On a 21:9 screen, the player can keep the game's HUD in the middle 16:9.
`inHudFrame(player, true)` draws your interface in that same frame, so a panel
aligned to the top right corner lines up with the game's own HUD on every
screen:

```ts
inHudFrame(player, true)
show(
  player,
  <panel
    style={{ horizontalAlign: 'right', verticalAlign: 'top', margin: [24, 24, 0, 0] }}
  >
    <label>Round 2</label>
  </panel>,
)
```

Sometimes your mod places something that the interface does not draw, such as a
world preview or a camera's frame, and it needs to know where the screen put
your panels. `followPlacement` tells it. Its handler hears the screen's size,
the HUD's frame and the box of each element you named with `measure`, all in
layout units measured from the screen's top left corner. The handler hears the
whole placement first, and then hears it again whenever any part of it moves,
such as after the player changes resolution. The renderer reads the layout
after each draw and four times a second, and only while some mod follows it.

```ts
followPlacement(player, (player, { screen, hud, measured }) => {
  const box = measured.get('preview')
  if (box) aimPreview(player, box.x / screen.width, box.y / screen.height)
})
```

## Replace the top bar

The game's top bar shows each player's portrait. Under the portrait it shows
the player's chat line for a few seconds, and it shows a mark while their voice
plays. A mode that hides the top bar to draw its own score would lose those
voices and chat lines, so it can draw them again with two calls.
`showSpeakers` shows who is talking, and `showChatLines` shows the chat lines as
subtitles. Each subtitle sits low in the middle of the screen, a little above
the ability bar, and holds the speaker's small portrait, their name in their
team's color and the line itself, on a slim translucent band. The subtitles
hide while the player has the game's chat box open, because the chat box shows
the same history. Call both when the mod loads:

```ts
import { hideHudForAll, showChatLines, showSpeakers } from 'modlock'

hideHudForAll(['topBar'])
showChatLines()
showSpeakers()
```

At most four lines show at once. The newest is at the bottom, and older ones
are dimmer. A speaker's next line replaces their last one, and a long line
wraps. A line sent to the team shows only to the speaker's team, and a line sent
to all shows to everyone. A command such as `/help` does not show.

`showChatLines` takes these options:

- `{ seconds }` sets how long a line stays, 6 unless you set it.
- `{ lines }` sets how many lines show.
- `{ bottom }` moves the lines up from the bottom edge.
- `{ scale }` sizes each line's text, portrait, band and spacing together. At
  `0.8`, the text is 13 pixels tall on a band at most 448 pixels wide.
- `{ portraits: false }` leaves the portraits out.
- `{ speaker(speaker, viewer) }` decides how each speaker looks, for a mode
  whose sides are not the game's teams. It returns the name's `color`, the
  portrait's `hero` (0 hides the portrait), a `note` to show after the name, and
  whether the speaker is `out`.

`showSpeakers` stacks a row at the left edge of the screen for each player the
viewer hears. Each row holds the speaker's portrait in a green ring, their name
and the voice icon. A row stays for a moment after the voice stops, so it does
not blink off in a pause between words. The rows stay in slot order, so the
stack does not reorder as people talk over each other. The player's own game
shows and hides each row from the voice marks on the hidden top bar, so your mod
does no work when a voice starts or stops. `{ scale }` sizes the rows, and
`{ speaker }` takes the same function as `showChatLines`, so a player looks the
same in both.

The library draws the chat lines and the speakers as layers of their own, over
whatever interface your mod shows each player, in the same way it draws toasts.
So a line arriving or leaving redraws only the lines, and your mod does not
redraw anything for it. A player's own `hideHud` list adds to the parts hidden
from everyone, and `hide` leaves all of those parts hidden.

## Inputs

Each input passes every change to its `onChange(player, value)`:

| Input        | Props                               | Value                                    |
| ------------ | ----------------------------------- | ---------------------------------------- |
| `<entry>`    | `value`, `placeholder`, `maxLength` | Text, cut to `maxLength` characters.     |
| `<slider>`   | `value`, `min`, `max`, `step`       | A number, clamped to the range and step. |
| `<range>`    | `handles`, `min`, `max`, `step`     | Every handle's number, in order.         |
| `<toggle>`   | `on`, label as children             | On or off.                               |
| `<dropdown>` | `options`, `selected`               | The chosen option's index.               |

The host drops a change to a disabled input, and a change to an input the
player no longer sees. The player's edit stays on their screen until your mod
draws a new value. So store each value your handler receives, and draw it back
into the input.

An entry or a slider waits until the player has stopped editing for a tenth of
a second, then sends their run of edits as one change. It sends at once when it
loses the keyboard, or when the player presses a button in the same interface.
So when the player presses a Save or Apply button, its `onPress` runs after the
`onChange` of every value the player sees.

A range is a track with one to eight named handles, such as a minimum, a
favored value and a maximum:

```tsx
<range
  handles={[
    { name: 'min', value: 0.2 },
    { name: 'favored', value: 0.5 },
    { name: 'max', value: 0.8 },
  ]}
  step={0.05}
  onChange={(player, [min, favored, max]) => save(player, min, favored, max)}
  onHold={(player, handle, phase) => preview(player, handle, phase)}
/>
```

The player drags one handle at a time, and a handle stops when it reaches its
neighbor. The handle keeps following the pointer past the track's ends, so the
player can push it to the end without aiming. When the player lets go,
`onChange` runs once with every handle's value. `onHold` hears each grab,
release and cancellation, with the handle's name. The drag is cancelled when a
stock overlay opens, when the menu closes or when your mod disables the range,
and the handles go back to where your mod last drew them. While the player
holds a handle, a redraw leaves the handles where the player has them. If you
change the handles' names, the player sees a new range.

The range is a single stop in the game's keyboard and controller navigation.
While it has the focus, left and right move its active handle by `step`, or by
a twentieth of the track when it has no `step`, and the handle still stops at
its neighbors. Enter, or the controller's confirm button, makes the next handle
active, and the active handle shows an outline. Each step runs `onChange` with
every value at once, and `onHold` hears it as a release. In Python the element
is `range_`, and in Go it is `ui.Range`.

In TypeScript, a form can decide where the keyboard goes. `focusOrder` on a
button or an input sets its place in the game's keyboard and controller
navigation, lowest first. `initialFocus` gives a control the keyboard when its
menu opens. A button with `submits` is pressed when the player presses Enter in
an entry of the same menu, after the entry's edit has been sent. So the player
can type a name and press Enter to save it. Escape still closes the menu, and
it does not call the mod.

## Long lists

A list shows more rows than an interface may hold as nodes, such as a
leaderboard of every player, and the player scrolls through them. You draw
every row from one template, whose text, images and variables refer to the
row's fields as `{field}`:

```tsx
<list
  style={{ height: 400 }}
  rowHeight={32}
  row={<label>{'{name}: {score}'}</label>}
  rows={players.map((p) => ({
    key: p.id,
    rank: -p.score,
    fields: { name: p.name, score: String(p.score) },
  }))}
/>
```

The list sorts its rows by `rank`, then by `sort`, then by `key`, and the `key`
tells the list which row is which as the rows change. When two rows have the
same key, the last one counts. The library in your mod holds every row. The
list's node carries only the window of rows near the part of the list that
shows, and as the player scrolls with the mouse wheel, their game asks your mod
for a new window. So a list of ten thousand rows costs your mod's draw and the
player's game what a list of a hundred rows does.

The library sorts an array of rows once, and when the rows are already in order,
the sort takes one pass over them. A draw that passes the same `rows` array
again costs only its window, even after draws without the list. So keep the
array while its rows stay the same, and pass a new array to change them. Go and Python cannot tell that a draw passes the same array, so in those
languages you make the rows once as a value, with `ui.NewRows` in Go or
`ui.Rows` in Python. A draw that passes the same value again also costs only its
window.

`rowHeight` sets every row's height, from 1 to 1000 pixels, and the list's own
`height` sets how much of the list shows. The template is a panel, label or
image holding at most fifteen more of them, and it cannot hold a button or an
input. A row has at most sixteen fields. The host takes at most 20,000 rows in
one list and a window of at most 256 rows, with at most 2 MiB of rows across one
player's interface. In Python the element is `list_`, and in Go it is `ui.List`.

The player focuses a row with the arrow keys or the controller. They choose it
with Enter, the controller's confirm button or a click. A choice runs
`onChange` with the row's key, and the mod draws that key back as `selected`,
in the same way an input draws back its value:

```tsx
<list
  rowHeight={32}
  row={<label>{'{name}'}</label>}
  rows={rows}
  selected={chosen}
  focusStyle={{ background: '#ffffff22' }}
  selectedStyle={{ color: '#ffd24a' }}
  onChange={(player, key) => {
    chosen = key
  }}
/>
```

`focusStyle` is drawn over a row's style while the player focuses the row, and
`selectedStyle` while the row is selected. The player's game holds the focus,
and it keeps the focus on the same row as rows are added, removed or reordered
above it. When the focused row leaves the list, the focus moves to the row that
took its place. When the list does not hold the selected key, no row shows as
selected.

## Local menus and portable text

A TypeScript `<menu>` gives the player a cursor to change settings or read a
result, and gives the mouse back when they are done, without a round trip to
the server. Its `mode` decides how it opens:

- `mode="toggle"` opens the menu on one press of the game's scoreboard binding
  (Tab by default) and closes it on the next.
- `mode="hold"` keeps the menu open while the player holds that binding.
- `mode="manual"`, the default, opens the menu from its optional `openLabel`
  button when the player already has a cursor, or when its `openRequest`, a
  positive number, increases.

For a manual menu, keep the menu's JSX key the same between draws, and increase
`openRequest` once for each new result, not on every redraw. If the shop, chat
or another menu has the cursor when a request arrives, the request waits, and
the menu opens once they close, unless your mod has stopped drawing it by then.
Only one request waits at a time.

A menu's `priority` orders your own menus. A request waits while one of your
menus with a higher priority is open, and otherwise it replaces the open menu.
So an alert at priority 2 can interrupt a warning at priority 1, and the warning
waits behind the alert. A request always waits while another mod's menu is
open, and the game's own interface always comes first. Put a `<menuClose>`
inside a menu to give it a button that closes it. The menu also closes on the
player's screen without asking the mod when the player presses Escape, when one
of the game's overlays takes the focus, or when the menu's surface goes away. A
menu that closes never calls the mod.

`<documentOutput text={text} />` shows plain text that the player can select
and copy with the game's usual controls, such as an export. `<documentInput>`
gives the player a draft of several lines to type or paste into. It sends
nothing while they type or paste, or when they press Enter in the draft.
Instead, the form's button sends the whole draft to `onSubmit(player, text)`.
`submitLabel` sets the button's text, `"Submit"` by default. Use `placeholder`
to show the format you expect, and `disabled` to stop editing and sending for a
while. Each player can have one document input and one document output for
each mod. Each holds at most 262,144 UTF-8 bytes (256 KiB), while an ordinary
`<entry>` keeps its short limit.

Each submission ends in exactly one callback. When the whole document arrives,
it reaches `onSubmit(player, text)`. Any other ending calls
`onFailure(player, failure)` with one of these reasons:

- `tooLarge`: the draft was past the limit.
- `expired`: the transfer did not finish in time.
- `cancelled`: the player closed the menu while the draft was sending.
- `malformed`: frames were missing, or were not text.

A transfer has 20 seconds plus its sending time, which is about one second for
each 14,400 bytes, so a full-size document has about 38 seconds. Show the player
the outcome from these callbacks, because the renderer knows only that it sent
the draft. When your mod replaces or removes the form during a submission, the
submission ends without a callback.

Check the document's contents in your mod, and ask the player to confirm before
it replaces a saved record. The host checks that the sending player still
has the current form, and not how the player entered the text. Neither control
gives a mod access to the player's clipboard.

To try these controls, run `modlock dev examples/interface-session`. The
example echoes back the text you give it, and saves nothing.

## The HUD kit

The HUD kit draws components that look like the game's own HUD. This sample
draws a round's score across the top of the screen:

<Samples>

```tsx
import { Score, show, TopStrip } from 'modlock'

show(
  player,
  <TopStrip heading="Round 2">
    <Score points={[1, 0]} />
  </TopStrip>,
)
```

```luau
local hud = require("@modlock/hud")

ui.show(player, hud.TopStrip { heading = "Round 2", hud.Score { points = { 1, 0 } } })
```

```python
from modlock.hud import score, top_strip

show(player, top_strip(heading="Round 2")[score(points=(1, 0))])
```

```go
// import "github.com/paralin/modlock/mod/hud"
ui.Show(p, hud.TopStrip{Heading: "Round 2", Children: hud.Score{Points: [2]int{1, 0}}})
```

</Samples>

| Component               | Draws                                                                        |
| ----------------------- | ---------------------------------------------------------------------------- |
| `<Text role>`           | Text in one of the kit's type roles.                                         |
| `<Plate>`, `<Pill>`     | A dark plate under text, so the text stays readable over a bright sky.       |
| `<Pips>`                | A count, drawn the way the round counter draws it.                           |
| `<Tag>`                 | A status label.                                                              |
| `<Banner>`              | An announcement of a moment.                                                 |
| `<TopStrip>`, `<Score>` | The top of the screen, with a score in it.                                   |
| `<Roster>`              | The players down the top right corner, with hero portraits.                  |
| `<Action kind>`         | A button in the game's menu look, with its hover, sounds and disabled state. |
| `<Meter value>`         | A bar that eases to each new value.                                          |

`theme` contains the tokens for your mod's own panels, such as `theme.tones`
and `theme.sizes`, and each entry in `heroes` has its small `portrait`.
[Layouts](/guides/layouts) describes layouts from the mod's content, style
sheets, and how the game draws an interface.

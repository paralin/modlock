---
title: Reloads and failures
description: What a reload resets, how to carry state across one, and what a failed call does.
---

While the game runs, `modlock dev` reloads your mod with the new build each time you save. A reload starts the mod fresh. Its variables reset, and the host removes everything the mod placed.

## Failed calls

A call that fails logs the reason and returns `false` or `undefined`, and your mod keeps running.

When the world changes, the host removes everything your mod placed. Stopping or reloading the mod removes it too. It also releases the heroes the mod froze, the modifier states it held and the input it blocked.

<Only lang="go">
  In Go, each call returns an error instead, and your mod can ignore the error
  and keep playing.
</Only>

## Slow and stopped mods

An event's processor time includes the game calls that its handler makes. It
does not include a stall where the server waits, such as paging on a machine
short of memory.

| An event that                      | Does                                                                                                                                                   |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| runs past 500 ms of processor time | Still finishes. The host logs where its time went, warns the players in chat, and for five minutes lets any player restart the mod with `/restartmod`. |
| runs past five seconds             | Stops the mod, as a crash does.                                                                                                                        |

When a mod stops, the host removes what it placed and the interfaces it showed,
and the mod stays stopped. The host warns in chat each minute until a player
types `/restartmod` or a reload replaces the mod. A restart starts the same
build in a new instance, as a reload does.

A frame handler has a much smaller allowance than an event. When it runs past 8
ms, the mod skips frames to repay the time. See
[The frame budget](/performance/frame-budget).

## Restart a running mod

A program that hosts mods can restart one in place with `WasmHost::Restart(mod)`, without restarting the server. It might do this when a mod's frames have grown slow over a long game. The restart runs on the mod's next frame. A new instance of the running build starts, and every value the old code kept is gone. The new instance hears the loaded world and the players, as a fresh start does. Its handoff state, scope and players' settings carry over, as they do through a reload. A stopped mod starts again.

A restart honors the mod's [reload hold](#hold-a-reload). While the mod holds its build, the restart waits, and it runs on the first frame after the mod releases the hold. `Restart(mod, true)` restarts the mod despite the hold. Asking again while a restart waits changes nothing, except that passing `true` ends the wait. `Held(mod)` reports whether the mod holds its build, and `Restarting(mod)` reports whether a restart is waiting.

## Hold a reload

When a new build would lose work in progress, such as a timed run, call `holdReload(true)` as the work starts and `holdReload(false)` when it ends. A reload that arrives while the hold is on waits. Then the newest build replaces the running one on the next frame after you release the hold. A restart that the host asks for waits the same way, unless the host forces it. A mod that stops also releases its hold.

<Samples>

```ts
import { holdReload } from 'modlock'

function startRun() {
  holdReload(true)
}

function endRun() {
  holdReload(false)
}
```

```luau
local function startRun()
	modlock.holdReload(true)
end

local function endRun()
	modlock.holdReload(false)
end
```

```python
def start_run() -> None:
    modlock.hold_reload(True)


def end_run() -> None:
    modlock.hold_reload(False)
```

```go
func startRun() { _ = mod.HoldReload(true) }

func endRun() { _ = mod.HoldReload(false) }
```

</Samples>

## Hand state to the next build

Some state should survive a reload, such as the round the game is on or the
panels each player has open. Hand that state to the next build as handoff state:

<Samples>

```ts
import { handedOff, handoff } from 'modlock'

// Pick up the round the last build was on.
let round = Number(handedOff() ?? 1)

function nextRound() {
  round += 1
  handoff(String(round))
}
```

```luau
-- Pick up the round the last build was on.
local round = tonumber(modlock.handedOff()) or 1

local function nextRound()
	round += 1
	modlock.handoff(tostring(round))
end
```

```python
# Pick up the round the last build was on.
round_number = int(modlock.handed_off() or 1)


def next_round() -> None:
    global round_number
    round_number += 1
    modlock.handoff(str(round_number))
```

```go
var round = 1

func init() {
	// Pick up the round the last build was on.
	mod.OnStart(func([]string) {
		if text, err := mod.HandedOff(); err == nil {
			if n, err := strconv.Atoi(text); err == nil {
				round = n
			}
		}
	})
}

func nextRound() {
	round++
	_ = mod.Handoff(strconv.Itoa(round))
}
```

</Samples>

| Call                                         | Does                                           | Ends when                             |
| -------------------------------------------- | ---------------------------------------------- | ------------------------------------- |
| `handoff(text)`, `handedOff()`               | Write the game's state, and read it on load.   | The mod stops or the server restarts. |
| `player.handoff(text)`, `player.handedOff()` | Write one player's state, and read it on load. | That player leaves. A bot has none.   |

Handoff state lasts only through a reload in the same game. The host keeps it
only in memory, up to 64 KiB per call. Handing off an empty text clears it.

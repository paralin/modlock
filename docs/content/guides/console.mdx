---
title: Console
description: Set console variables and run commands, within limits.
---

The `modlock/console` module sets the game's console variables and runs its
console commands. The setter for each variable takes the type the game declares
for it.

<Samples>

```ts
import { run, set } from 'modlock/console'

set('citadel_allow_purchasing_anywhere', true)
set('citadel_trooper_gold_reward', 40)
run('changelevel', 'street_test')
```

```luau
local console = require("@modlock/console")

console.setBoolean("citadel_allow_purchasing_anywhere", true)
console.setNumber("citadel_trooper_gold_reward", 40)
console.run("changelevel", "street_test")
```

```python
from modlock import console

console.set_boolean("citadel_allow_purchasing_anywhere", True)
console.set_number("citadel_trooper_gold_reward", 40)
console.run("changelevel", "street_test")
```

```go
import "github.com/paralin/modlock/mod/console"

_ = console.CitadelAllowPurchasingAnywhere.Set(true)
_ = console.CitadelTrooperGoldReward.Set(40)
_ = console.Changelevel.Run("street_test")
```

</Samples>

Every call runs one console line through `serverCommand`, and `serverCommand`
can also set a development-only or cheat-protected variable. A variable whose
value is a vector or a color does not have a typed setter, so set it with
`serverCommand` yourself.

## Set up a mode

`apply(settings)` sets several variables in order and returns the names of the
ones the server refused. For a custom mode, start from `arena`, which empties
the map. With `arena`, the server keeps running when no one is connected, and no
troopers, neutrals, practice bots or zipline starts appear. Spread `arena` into
your settings and add your mode's own:

<Samples>

```ts
import { apply, arena } from 'modlock/console'

apply({ ...arena, citadel_allow_duplicate_heroes: true })
```

```luau
local console = require("@modlock/console")

-- When two tables set the same variable, the later table's value wins.
console.apply(console.arena, { citadel_allow_duplicate_heroes = true })
```

```python
from modlock import console

console.apply({**console.ARENA, "citadel_allow_duplicate_heroes": True})
```

```go
import "github.com/paralin/modlock/mod/console"

// Arena returns its settings as a slice, and To makes a setting of your own.
console.Apply(append(console.Arena(), console.CitadelAllowDuplicateHeroes.To(true))...)
```

</Samples>

## Record a replay

Hyperline does not record the games it hosts, so a mod that wants a replay
records one itself. Turn on SourceTV, then start the recording under a name
made of letters, digits, `-` and `_`. Give each recording its own name, such as
the mod's slug and a round number, so one recording never overwrites another:

<Samples>

```ts
import { run, set } from 'modlock/console'

function record(name: string): void {
  set('tv_enable_dynamic', true)
  set('tv_delay', 0)
  set('tv_transmitall', true)
  set('tv_enable', true)
  run('tv_record', name)
}

record('my-mod-round-1')
```

```luau
local console = require("@modlock/console")

local function record(name: string)
	console.setBoolean("tv_enable_dynamic", true)
	console.setNumber("tv_delay", 0)
	console.setBoolean("tv_transmitall", true)
	console.setBoolean("tv_enable", true)
	console.run("tv_record", name)
end

record("my-mod-round-1")
```

```python
from modlock import console


def record(name: str) -> None:
    console.set_boolean("tv_enable_dynamic", True)
    console.set_number("tv_delay", 0)
    console.set_boolean("tv_transmitall", True)
    console.set_boolean("tv_enable", True)
    console.run("tv_record", name)


record("my-mod-round-1")
```

```go
import "github.com/paralin/modlock/mod/console"

func record(name string) {
	_ = console.TvEnableDynamic.Set(true)
	_ = console.TvDelay.Set(0)
	_ = console.TvTransmitall.Set(true)
	_ = console.TvEnable.Set(true)
	_ = console.TvRecord.Run(name)
}

record("my-mod-round-1")
```

</Samples>

`tv_enable_dynamic` starts SourceTV without a map change. `tv_delay 0` records
play as it happens. `tv_transmitall` keeps the whole map in the recording,
rather than one team's view. `tv_stoprecord` ends the recording. Without it, the
recording ends when the map or the server does. Start the recording from a
setting players choose, so a lobby records only when its leader asks.

The recording is saved as `citadel/<name>.dem` on the PC or server that runs
the game. When a lobby plays on its leader's PC, the leader has the file. When
the game runs on one of Hyperline's game servers, as every game of a
`dedicatedOnly` [placement](/reference/manifest#placement) does, the file stays
where players cannot reach it. Ask for it in the
[Hyperline Discord](https://discord.gg/DCErWrCFvh) after the session.

## Limits

Your mod's console lines can change the game, but nothing outside it. They may
set the game's rules and bots, change or reload the map, kick a player, quit the
game and set the time scale. They may also start the game's own recording with
`tv_enable` and `tv_record <name>`, where the name contains only letters,
digits, `-` and `_`. They may not reach:

| Area                      | Refused                                                                                                                                                |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Files                     | `exec` and its kin, saves, demo playback, config and path variables, and file-writing commands such as `condump` or `writeip`                          |
| Logging                   | `log`, `log_*`, `con_log*`, `sv_log*`, and console redirection                                                                                         |
| The network               | `connect`, `rcon*`, addresses and ports, IP bans, passwords, Steam account and group settings, and broadcast, relay and playcast `tv_*` settings       |
| The process               | Crash and minidump commands, debuggers, tools, and shutdown                                                                                            |
| Lines stored to run later | `alias`, `cmd`, `bind*`, `unbind*`, `execute_command_every_frame`, and the test script's `test_*` commands, which run the commands they take           |
| Entities                  | `ent_create`, `ent_fire*`, `ent_call`, `firetarget`, and `give` for a class [`createEntity` refuses](/guides/entities#create-entities-and-send-inputs) |
| The script VM             | `script_*`                                                                                                                                             |

`toggle`, `incrementvar` and `multvar` set the variable they take, so the server
refuses each of them for a variable your mod may not set directly. The server
checks every command in a line, after each `;` or newline. When it refuses a
line, the error names the first command it refused.

---
title: Publishing
description: Release a mod for others to play.
---

`modlock publish` builds the mod and runs the same check that every host runs
before loading a mod. The module may import only Modlock and WASI functions, and
it must start and answer its first event within the time limits. Then the
command uploads the mod to the destination you choose with `--to`:

| `--to`      | Effect                                                                                           |
| ----------- | ------------------------------------------------------------------------------------------------ |
| `hyperline` | The default. Upload the mod to [hyperline.gg](https://hyperline.gg).                             |
| `archive`   | Write `SLUG-VERSION.zip` to `--out`: the mod, `modlock.exe` and `Play.cmd` to run it on Windows. |
| `github`    | Attach that zip to the GitHub release `SLUG-vVERSION`, creating the release if needed.           |

On your first upload to hyperline.gg, the command opens your browser to sign
in, as `modlock login` does, and saves the sign-in for later commands. During
the alpha, you can publish there only once you have access. Ask for access in
the [Hyperline Discord](https://discord.gg/DCErWrCFvh). To publish to
another service with the same API, pass its address with `--origin`. The
`github` destination publishes with the [`gh`](https://cli.github.com) command
line, signed in as `gh` is.

The build copies every field that Modlock itself does not read, such as a
description for a store, into the built `mod.json`, and the destination reads
those fields there. Hyperline accepts each version only once, so raise
`version` in `mod.json` before you publish again.

Pass `--notes` to say what changed. hyperline.gg shows the notes on the game's
page, and the `github` destination puts them on the new release.

`--prerelease` publishes a version such as `0.2.0-pre.1` to hyperline.gg for the
mod's testers only. Existing lobbies keep playing the current release. For each
game in the mod, hyperline.gg creates a Draft copy running the prerelease (such
as "Zombie Tag Prerelease"), which testers can invite others to join. A newer
prerelease replaces the previous one. Promoting the Draft copy on hyperline.gg
makes that build the current release without republishing.

After the upload, `modlock publish` tells you where players can play the
release. A mod with code plays on hyperline.gg's game servers at once, and on
players' own PCs once a reviewer approves it. A trusted creator's releases play
everywhere as soon as they are published. When your mod has its own layouts,
models or sounds, `modlock publish` uploads them with it, as
[client content](/guides/client-content) explains.

## Your team

Each mod on hyperline.gg has an owner, developers and testers, listed under
Team on the mod's page:

| Role      | Permissions                                                                                                        | Requirements   |
| --------- | ------------------------------------------------------------------------------------------------------------------ | -------------- |
| Owner     | Everything a developer can do, plus transferring ownership to another developer. The mod's games credit the owner. | Creator access |
| Developer | Publish releases, edit game status and pages, play Draft games, and add or remove developers and testers.          | Creator access |
| Tester    | View and launch the mod's Draft games and prereleases, and invite others into them.                                | Sign-in only   |

Whoever first publishes a mod becomes its owner. A player must sign in to
hyperline.gg once before you can add them to the team, and a developer also
requires Creator access granted by administrators. The owner cannot be removed;
to transfer ownership, assign the new owner first (the previous owner remains a
developer). Hyperline owns its own official mods, so only administrators can
transfer them.

| Command                 | Effect                                                                                                                                                                                                                                                                                                          |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `modlock new [DIR]`     | Create a mod project, prompting for its name and language, then offering to install the editor extension and open the project in VS Code. Pass `--name` and `--language` to skip prompts. Non-interactive runs (including `--json`) do not prompt, so they require `DIR` and default to TypeScript unless `--language` is given. |
| `modlock build`         | Check the mod and write the built mod to `build/`.                                                                                                                                                                                                                                                              |
| `modlock dev [DIR]`     | Build the mod, run it in a local server, join it, and reload it on each save.                                                                                                                                                                                                                                   |
| `modlock play [MOD...]` | Play locally. Each `MOD` is a project or a built mod's directory, by default the current one. Only one of them can be a watched project.                                                                                                                                                                        |
| `modlock join CODE`     | Join a session another PC hosts, by its join code or its lobby's link, and launch Deadlock into it. With `--no-game`, it prints the `connect` line to enter in a running game's console instead of launching Deadlock.                                                                                          |
| `modlock publish [DIR]` | Build and check the mod, then [publish it](/reference/publishing).                                                                                                                                                                                                                                              |
| `modlock editor`        | Install the Modlock extension, and in a mod project its language's extension, into VS Code, VS Code Insiders, Cursor, Windsurf or VSCodium: the active terminal's editor, or all installed editors. `--editor` picks one: `code`, `code-insiders`, `cursor`, `windsurf` or `codium`. |
| `modlock login`         | Sign in to hyperline.gg in the browser. `--host`, `join` and `publish` then use that sign-in.                                                                                                                                                                                    |
| `modlock logout`        | Remove the saved sign-in. `--host` and `join` then connect the PCs directly.                                                                                                                                                                                                     |
| `modlock update`        | Install the newest release over this `modlock`. `--check` only reports whether a newer release is out. `--release v0.1.9` installs that one. A [channel](#where-it-lives-and-how-it-updates) selects between tagged releases and `master` branch builds.                         |
| `modlock version`       | Print the version, as `modlock --version` does.                                                                                                                                                                                                                                  |
| `modlock config`        | List the settings. `modlock config set update-check off` disables update checks, and `editor-offer off` disables editor extension prompts in `new`, `dev`, and `play`.                                                                                                         |
| `modlock daemon`        | `status` shows the background process that keeps this PC's mod store and its connection to other PCs. `probe PEER` measures the link to another PC. `stop` ends it.                                                                                                                                             |
| `modlock lfs setup`     | Keep this Git repository's LFS files in this PC's mod store, so `git push` sends the remote only their pointers.                                                                                                                                                                                                |

When Deadlock is not installed, `dev` and `play` run your mod in the sandbox instead. Both take these options:

| Option                | Effect                                                                                                   |
| --------------------- | -------------------------------------------------------------------------------------------------------- |
| `--no-game`           | Run the server without launching Deadlock.                                                               |
| `--port PORT`         | Serve on a UDP port other than 27067.                                                                    |
| `--sandbox`           | Run in the sandbox even when the game is installed.                                                      |
| `--watch=false`       | Build once instead of reloading on each save. `play` then runs existing builds and can run several mods. |
| `--release`           | Build as `publish` does.                                                                                 |
| `--host`, `--lobby`   | `play` only. Let friends join with a join code, or through a Hyperline lobby.                            |
| `--ui-port PORT`      | Serve the mods' interfaces to the game on a port other than 4320. `0` turns them off.                    |
| `--ui-relay ORIGIN`   | Reach the interfaces through a site other than `https://hyperline.gg`.                                   |
| `--preview-port PORT` | Serve the browser preview of the interface on a port other than 4322. `0` turns it off.                  |
| `-- ARG...`           | Pass the words after `--` to the mods' `onStart` handlers, as in `modlock dev -- probe 4`.               |

While `dev` or `play` watches a project, saving a file rebuilds the mod and replaces the running one. Saving a file in `build/` or `node_modules`, a hidden file or a `*.log` file does not. The terminal shows the mod's log, its reloads and the players who join. The server's own console output goes to `build/server.log`.

In the sandbox, a line you type in the terminal is sent as chat from the stand-in player. In a game, the line reaches the mods as a console command from the connected player in the lowest slot. The presses and commands sent from the preview page reach the mods the same way. The terminal tells you when no player is in the game or no mod took the command.

In a Python mod, a line starting with `>` executes in `main.py`'s module like an
interactive Python REPL (for example, `> modlock.players()` prints the player
list). Exceptions print a traceback without stopping the mod. This REPL is
currently Python-only.

[Playing together](/reference/play-together) explains `--lobby`, `--host` and `join`. `join` also takes `--ui-port` and `--ui-relay`. `login`, `join` and `publish` take `--origin`, to use a site other than `https://hyperline.gg`.

| Variable                  | Use it when                                                                          |
| ------------------------- | ------------------------------------------------------------------------------------ |
| `DEADLOCK_DIR`            | Deadlock is installed outside the Steam libraries.                                   |
| `MODLOCK_HOST`            | You built `modlock-host.exe` yourself. The sandbox reads the interpreters beside it. |
| `MODLOCK_PROTON`          | You want a particular Proton installation.                                           |
| `MODLOCK_NO_UPDATE_CHECK` | You want to turn off the check for a newer release in this environment.              |

## Where it lives and how it updates

On Windows, the installer puts `modlock` in `%LOCALAPPDATA%\Programs\modlock` and adds that directory to your `PATH`. There, `modlock` starts the game server directly. On macOS and Linux, the installer puts `modlock` in `~/.local/bin`. On Linux, `modlock` starts the Windows game server through Steam's Proton.

At most once a day, `modlock` checks in the background for a newer release, and tells you when one is out. It skips the check in CI, when `MODLOCK_NO_UPDATE_CHECK` is set, and after `modlock config set update-check off`.

`modlock update` installs from a channel, which is either releases or builds of the master branch. It remembers the channel you choose, and the daily check uses that channel too:

| Command                             | Does                                                                                                              |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `modlock update --channel master`   | Installs the build of the master branch's newest commit. Its version reads `master-` and 12 digits of the commit. |
| `modlock update --channel stable`   | Goes back to releases, the default channel.                                                                       |
| `modlock config set channel master` | Sets the channel without updating.                                                                                |
| `modlock update --from-source`      | Builds the master branch on your computer, which needs Git, Go, Zig, CMake and Ninja.                             |

## Game files

These commands read and write the game's own file formats, and they work without the game or Valve's tools installed.

| Command                                    | Effect                                                                                                                                            |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `modlock panorama compile DIR`             | Compile the Panorama layouts (`.xml`), scripts (`.js`) and style sheets (`.css`) under `DIR/panorama/` into `DIR.vpk`.                            |
| `modlock panorama decompile FILE`          | Print a compiled layout (`.vxml_c`) as XML, a script (`.vjs_c`) as its source, or a style sheet (`.vcss_c`) as CSS.                               |
| `modlock vpk list ARCHIVE`                 | List an archive's files and their sizes.                                                                                                          |
| `modlock vpk unpack ARCHIVE DIR [PATH...]` | Write the archive's files, or those under each `PATH`, into `DIR`. `--decompile` writes Panorama files as source and textures as PNG beside them. |
| `modlock vpk pack DIR ARCHIVE`             | Pack a directory into an archive. Equal directories pack to equal bytes.                                                                          |
| `modlock kv3 FILE`                         | Print a compiled resource's KeyValues3 data as JSON. `--blocks` lists its blocks.                                                                 |
| `modlock texture FILE`                     | Decode a compiled texture (`.vtex_c`) to a PNG of its largest mip; `-o` specifies the output path.                                              |
| `modlock studio`                           | Browse game assets and preview models, textures and sounds in Modlock Studio.                                                                     |
| `modlock studio render [NAME=]MODEL...`    | Render models from the game's archive to PNG files with a transparent background.                                                                 |

`panorama compile` copies every other file in `DIR` into the archive unchanged, so compiled assets such as images can sit beside the layouts. `-o` writes to a different archive or directory.

A style sheet's `url()` can reference an image or another sheet in the game's files, written as `s2r://`, `file://{images}/` or `file://{resources}/`. The compiler rewrites the URL to the path of the resource the game loads, so `file://{images}/icons/mark.png` becomes `s2r://panorama/images/icons/mark_png.vtex`. For each referenced image, the compiler also records its dimensions, which the engine uses at runtime. The compiler reads the size from the compiled image in `DIR`, or, for one of the game's own images, from your Deadlock install. Without an install, the compiler omits the image size from the sheet, and the game reads it when the image loads. The compiler rejects any other URL and reports its line.

`decompile`, `kv3` and `texture` take `--archive` to read `FILE` from inside an archive, including the game's split `game/citadel/pak01_dir.vpk`:

```sh
modlock panorama decompile --archive pak01_dir.vpk panorama/layout/hud.vxml_c
```

`modlock studio` prints a local address to open in a browser. Modlock Studio:

- lists every file in the installed game's archive,
- draws models with their levels of detail, mesh groups and materials,
- shows textures as the GPU stores them,
- plays and downloads MP3 and PCM sounds,
- shows other resources' KeyValues3.

Modlock does not bundle any game assets; Studio reads them directly from your local Deadlock installation when you open them. `--port` serves Studio on another port, and setting `DEADLOCK_DIR` points Studio at a game installed outside the Steam libraries.

`modlock studio render` draws each model in a headless Chromium. It draws each model alone, lit by a light rig that turns with the camera. It trims the picture to an even margin and saves it as `NAME-VIEW.png`. `MODEL` is an archive path or a pattern such as `models/props_street/*.vmdl_c`, and `--list` reads more models from a file, one per line.

A `--view NAME:YAW:PITCH` places the camera, in degrees. Yaw 0 looks at the model's front, and positive yaw turns counterclockwise as seen from above, toward the model's left. The default views are `left:35:15` and `right:-35:15`. `--turntable N` adds `N` evenly spaced views, and `--size`, `--margin` and `--fov` set the picture. Pass Chromium's path with `--browser` when it is not on the `PATH`, or pass `--browser none` to open the printed address yourself:

```sh
modlock studio render --out props --turntable 8 crate=models/props/wooden_crate_a.vmdl_c
```

When your mod tracks large files, such as VPKs, with Git LFS, you can keep them out of its Git remote. After `git lfs track`, run `modlock lfs setup` in the repository once. From then on, Git LFS hands each file to `modlock`, which stores it in this PC's mod store. In a fresh clone, run the same setup before `git lfs pull`. `modlock` stores each file by its content, so a file that several repositories share is stored only once. The files stay on this PC, so a clone on another PC can pull them only from that PC's own store.

A TypeScript or JavaScript mod imports `modlock` and registers its handlers
when it loads:

```ts
import { command } from 'modlock'

command('hello', (player) => {
  player.chat('Hello from TypeScript!')
})
```

Choose the language with the switch in the sidebar, and the
[guides](/guides/events) show every call in TypeScript and JavaScript. Two
features exist only in TypeScript: [camera curves](/guides/camera), and
`ProbeRun` for [testing](/guides/testing).

## The build

The build starts from `main.ts` or `main.js` (checking JavaScript mods using
JSDoc comments). Each build writes the library's type definitions to
`node_modules/modlock` for your editor and type checker, then bundles your mod
with the runtime library embedded in `modlock`, requiring no external package
install.
[`src/wasm/wasm.proto`](https://github.com/paralin/modlock/blob/master/src/wasm/wasm.proto)
documents every call, its arguments, and its return type.

## Two runtimes

Every build bundles your mod for QuickJS, an interpreter that runs any
JavaScript with fast build times. If your mod's frame handlers are too slow, set
`"runtime": "RUNTIME_WASM"` in `mod.json`. Then `modlock publish` compiles the
mod ahead of time to WebAssembly with [scriptc](https://scriptc.dev), which
`modlock` downloads on first use. The compiled mod runs about 2.5 times faster,
but compilation takes around a minute and a few gigabytes of memory. Run
`modlock build --release` to test that build before publishing.

In the WebAssembly build, a file with `.wasm` before its extension overrides the
module of the same name (`bench.wasm.ts` replaces `bench.ts`, and `hud.wasm.tsx`
replaces `hud.tsx`). Use overrides to stub out code that `scriptc` cannot
compile and the published mod does not execute, such as a test harness, exporting
the same symbols from a smaller module while the QuickJS bundle keeps the
original.

The override file must be included by `tsconfig.json` (which is the default
unless `files` are listed explicitly), and it cannot import the module it
replaces because that path resolves to the override itself.

In two cases the build falls back to the QuickJS bundle, and `modlock publish`
refuses to upload it unless you pass `--allow-fallback`:

- `scriptc` cannot compile part of the mod. The build lists each unsupported
  construct and its location.
- The two builds diverge in behavior. To check equivalence, the build runs both
  in the sandbox through a start event, a player join, a world load, and five
  seconds of frames using a shared clock and identical random bytes. Each event
  runs in QuickJS first, and whenever the WebAssembly build makes the same
  host call, it receives the response QuickJS received. The build prints the
  first event where the two runtimes diverge in their calls or return values,
  along with the differing outputs. Consecutive server commands are compared as
  a set since their relative order does not affect game state. This verification
  compiles QuickJS using `scriptc`'s bundled Zig toolchain once per `scriptc`
  version.

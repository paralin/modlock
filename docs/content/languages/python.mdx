A Python mod imports `modlock` and registers its handlers with decorators in
`main.py`:

```python
import modlock


@modlock.command("hello")
def hello(player: modlock.Player, args: str) -> None:
    player.chat("Hello from Python!")
```

Choose Python with the switch in the sidebar, and the [guides](/guides/events)
show every call in Python.

## Types and modules

Pyright (and Pylance in VS Code) checks your mod's types.

| Report  | Cause                                                                                  | Effect                           |
| ------- | -------------------------------------------------------------------------------------- | -------------------------------- |
| Error   | Type mismatch.                                                                         | Fails the build.                 |
| Warning | Unhandled `None` (such as from `find_hero`) or an unannotated parameter.               | Prints a warning and continues.  |

For stricter or looser checking, edit `typeCheckingMode` and the report rules
in `pyrightconfig.json`. That file also points type checkers to `.modlock`. Type
checkers read `pyrightconfig.json` only from the workspace root, so open the
mod's directory directly; opening a parent directory causes `modlock` import
errors.

Modules import each other by name, such as `import round`. Mods run on Python
3.14 and can import standard library modules such as `dataclasses`, `enum`,
`json`, `math`, `random`, and `re`.

## Calls and types

The Python library mirrors the TypeScript API using `snake_case` names. Each
message is a dataclass, each enum is a set of string literals, and a 64-bit ID
is a Python integer. Build interfaces with `modlock.ui`, `modlock.hud`, and
`modlock.theme`.

```python
# Headshots deal double damage.
@modlock.on_damage
def headshots(hit: modlock.DamageEvent) -> modlock.DamageResult | None:
    if hit.hit_group == 1:
        return modlock.DamageResult(amount=hit.amount * 2)
    return None


# Pay a soul bonus on /bonus.
@modlock.command("bonus")
def bonus(player: modlock.Player, args: str) -> None:
    player.adjust_souls(500)
    player.announce("Bonus", "500 souls")


# Answer the attack button.
@modlock.on_input
def fire(
    player: modlock.Player, pressed: modlock.Buttons, released: modlock.Buttons
) -> None:
    if pressed & modlock.Buttons.ATTACK:
        player.center_text("Fire!")
```

## Typed entities and the console

`modlock.entities` has a class for each entity class, with its fields as
attributes, and it creates an entity from its designer name.
`modlock.console` sets console variables and runs console commands. Import each
one beside `modlock`:

```python
from modlock import console, entities

# Set a hero's health.
hero = entities.CCitadelPlayerPawn(pawn.entity)
hero.m_iHealth = 500

keys: entities.CNPC_TrooperBossKeys = {"LaneNum": 2}
boss = entities.create("npc_trooper_boss", modlock.Vector(x=0, y=0, z=0), keys=keys)

console.set_number("citadel_trooper_gold_reward", 40)
console.run("changelevel", "street_test")
```

If the server cannot read or write a field (such as `hero.m_iHealth` above),
reading returns `None`, writes are ignored, and the server log records the
reason.

## Interactive REPL

While `modlock dev` or `modlock play` runs, type a line starting with `>` in the
terminal to evaluate it inside `main.py`'s module:

```text
> modlock.players()
[Connection(player=Player(slot=0), name='Player', ...)]
> _[0].name
'Player'
> score["kills"] += 1
```

| Input         | Output                                                 |
| ------------- | ------------------------------------------------------ |
| an expression | its value, stored in `_` (`None` prints nothing)       |
| a statement   | nothing (updates module state)                         |
| a `print`     | the printed text                                       |
| an error      | its traceback, while the mod keeps running             |

The mod evaluates the line between frames, both in the sandbox and in the game.
This interactive prompt is available only for Python mods; other languages
report that no console is available.

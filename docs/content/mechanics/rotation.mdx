---
title: A rotation mode
description: Run a lobby through one fight at a time, with a fair line and balanced sides.
---

A rotation mode, such as a duel ring or a two against two pit, runs a lobby
through one fight at a time. A player joins the line, waits in the stands,
fights when their turn comes and goes to the back of the line again. The
TypeScript library has calls for each part of that:

| Piece                                | Call                                        |
| ------------------------------------ | ------------------------------------------- |
| Who is here                          | `Cast`                                      |
| Each player's record for the session | `Standings`, `Standing`                     |
| Waiting in the stands                | `holdBystander`, `playCamera`, `curve.hold` |
| Who fights next, and on which side   | `nextMatch`, `afterMatch`                   |
| An even share of heroes              | `leastUsed`                                 |
| The result                           | `settle`, `ratingChange`                    |
| The leaderboard                      | `leaderboard`, `Roster`                     |
| Heroes left behind by a swap         | `Strays`                                    |

The rotation calls exist only in TypeScript. Import them from `modlock/kit`,
along with `holdBystander` and `Strays`, and import `Cast`, `playCamera`,
`curve` and `Roster` from `modlock`. Each rotation call is pure. Your mod keeps
the line and the standings, and each call reads only what you pass it. Because
the calls are pure, `js/test/rotation.test.ts` runs a whole session without the
game.

## The line and the standings

A player's standing is their record for the session. It holds their matches
played, rating, wins, losses and current win streak. A `Standings` contains one
`Standing` for each Steam ID. Keep the line as an array of your own players, in
the order they arrived, beside one `Standings`:

- A player who leaves and rejoins keeps their record and place.
- `join` creates the standing at `startingRating`. Then it raises the player's
  matches played to the fewest that anyone present has played. So arriving late,
  or leaving to skip a turn, never jumps the line.
- A function passed to `Standings` adds your own fields to each new standing,
  such as matches played as each hero:

```ts
import { Cast } from 'modlock'
import { Standings } from 'modlock/kit'

const standings = new Standings(() => ({ heroes: [0, 0] }))
let line: Entrant[] = []

const cast = new Cast({
  join: ({ player, name, steamId }) => {
    const standing = standings.join(
      steamId,
      line.map((each) => each.standing),
    )
    const entrant = { player, name, standing }
    line.push(entrant)
    return entrant
  },
  leave: (entrant) => {
    line = line.filter((each) => each !== entrant)
  },
})
```

## The stands

A waiting player can sit in the stands, with a hero that the fight does not
use. `holdBystander(entity)` keeps that hero out of play, and
`holdBystander(entity, false)` gives it back before the player fights. A held
hero:

- cannot move, shoot, cast or zoom;
- cannot be targeted by either team's abilities, and bullets and melee pass
  over it;
- cannot be pulled from its seat by displacement.

Teleport the hero to its seat, facing the ring. Then aim `playCamera`'s
`target`, the point the camera turns around, at the ring's center, with a long
`distance`. The player circles that view with the mouse. Each param snaps back
when its curve ends, so hold each curve longer than any wait. Clear the context
when the player leaves the stands:

```ts
import {
  type Angles,
  curve,
  playCamera,
  type Player,
  type Vector,
} from 'modlock'
import { holdBystander } from 'modlock/kit'

const context = 'arena.stands'

function seat(
  player: Player,
  pawn: number,
  position: Vector,
  facing: Angles,
): boolean {
  player.teleport(position, facing)
  holdBystander(pawn)
  player.clearCamera(context)
  const move = playCamera(player, {
    context,
    priority: 4,
    tracks: {
      target: curve.hold({ x: 0, y: 0, z: 60 }, 3600),
      distance: curve.hold(1400, 3600),
      verticalOffset: curve.hold(0, 3600),
      horizontalOffset: curve.hold(0, 3600),
    },
  })
  return move !== undefined
}

function unseat(player: Player, pawn: number): void {
  holdBystander(pawn, false)
  player.clearCamera(context)
}
```

`playCamera` returns nothing while the player does not have a hero. So mark the
seat taken only once `seat` returns true, and try again each frame until it
does. A bystander can still die from a fall or world damage, so respawn it and
seat it again.

## The next match

When it is time for the next fight, `nextMatch(line, size, standing)` picks
who fights, in two steps:

1. It takes the `2 * size` players who have played the fewest matches. Among
   equals, the one earlier in the line goes first.
2. It deals them to the sides by rating in a snake (first, second, second,
   first), which keeps the sides' ratings close. With two per side, the best
   pairs with the worst against the middle two.

While too few players wait, `nextMatch` returns nothing, and your HUD can show
that the mode is waiting for players.

```ts
const sides = nextMatch(line, size, (each) => each.standing)
if (sides) {
  for (const fighter of sides.flat()) {
    fighter.standing.played++
  }
}
```

Count the match as played when it is seated, not when it ends. Then a fighter who leaves in the middle of a match still goes to the back of the order.

## An even share of heroes

When the mode picks each fighter's hero from a short list, count each player's
matches on each hero. `leastUsed(counts, prefer)` returns the hero the player
has played least, or `prefer` on a tie. So everyone plays every hero about
equally, and two fighters can start on different heroes by preferring
different ones.

```ts
const choice = leastUsed(fighter.standing.heroes, side === 0 ? 0 : 1)
fighter.standing.heroes[choice]++
```

## The result

When the fight ends, these calls record it and move the line on:

| Call                       | Does                                                                                                                                                                    |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `settle(winners, losers)`  | Moves both sides' ratings by the Elo step between their averages, larger for an upset; counts wins, losses and streaks; returns the change, for a banner such as `+16`. |
| `ratingChange`             | The same step alone.                                                                                                                                                    |
| `step` option              | Replaces `ratingStep` (32) for matches that should count more or less.                                                                                                  |
| `afterMatch(line, fought)` | Sends the fighters to the back of the line, everyone else keeping their order.                                                                                          |

```ts
const change = settle(
  winners.map((each) => each.standing),
  losers.map((each) => each.standing),
)
line = afterMatch(line, [...winners, ...losers])
```

## The leaderboard

`leaderboard(players, standing, rows, viewer)` ranks players by wins, then by
rating, and returns the first `rows`. When the viewer would fall off the list,
it keeps them on the last row. `Roster` draws each row's hero, avatar and a
line of activity. Its `groups` put players under headings, such as one for each
team. As players join, its rows shrink and then run in columns, so every row
fits between `top` and `bottom`. `rosterBottom` takes the same props and gives
the line where the roster ends, for a panel drawn under it:

```ts
const rows = leaderboard(line, (each) => each.standing, 8, viewer)
show(
  viewer.player,
  Roster({
    rows: rows.map((each) => ({
      name: each.name,
      self: each === viewer,
      hero: each.hero,
      steamId: each.steamId,
      activity: `${each.standing.wins}-${each.standing.losses} · ${each.standing.rating}`,
    })),
  }),
)
```

## Heroes left behind

Swapping a player's hero, or moving them to the spectators and back, can
leave the old hero without a player controlling it. The game still revives that
hero on its own timer. A hero belongs to a player while the player's controller
points to it, so a player who joins or spectates keeps their hero. Once a hero
has belonged to nobody for `strayGraceSeconds`, `Strays` kills it once and holds
off its respawn for good. The sweep checks once a second, with one entity
listing and two field reads for each hero. Keep one `Strays` and call
`sweep(now)` each frame:

```ts
import { onFrame } from 'modlock'
import { Strays } from 'modlock/kit'

const strays = new Strays()
onFrame(({ timeSeconds }) => strays.sweep(timeSeconds))
```

The sweep leaves a stray's abilities in place, because killing a live hero's
ability entities has crashed the server.

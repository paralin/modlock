---
title: A rotation mode
description: Run a lobby through one fight at a time, with a fair line and balanced sides.
---

A rotation mode runs a lobby through one fight at a time: a duel ring, a
king of the hill, a two against two pit. Everyone waits in one line. Each
match seats the players who have fought the least. The sides are split by a
session rating so neither stacks. The players not fighting watch from the
stands. This guide builds one from Modlock's pieces:

| Piece                                | Call                                        |
| ------------------------------------ | ------------------------------------------- |
| Who is here                          | `Cast`                                      |
| Each player's record for the session | `Standings`, `Standing`                     |
| Who fights next, and on which side   | `nextMatch`, `afterMatch`                   |
| The result                           | `settle`, `ratingChange`                    |
| An even share of heroes              | `leastUsed`                                 |
| The leaderboard                      | `leaderboard`, `Roster`, `rosterRows`       |
| Waiting in the stands                | `holdBystander`, `playCamera`, `curve.hold` |
| Heroes left behind by a swap         | `Strays`                                    |

The rotation calls are in the TypeScript library today. Each call is pure:
the mod keeps the line and the standings, and the call reads what it is
given. `js/test/rotation.test.ts` runs a whole session without the game.

## The line and the standings

Keep the line as an array of your own players, in arrival order. A
`Standings` holds one `Standing` per Steam ID for the session. A player who
leaves and rejoins keeps that record and their place in the order; they do
not start fresh.

`join` creates the standing at `startingRating` on the first join. It then
raises matches played to the fewest anyone present has played. Arriving
late, or leaving to skip a turn, never puts a player ahead of the line.

Pass `Standings` a function to add your own fields to each new standing, such
as matches played as each hero:

```ts
import { Cast, Standings } from 'modlock'

const standings = new Standings(() => ({ heroes: [0, 0] }))
let line: Entrant[] = []

const cast = new Cast({
  join: ({ player, name, steamId }) => {
    const standing = standings.join(
      steamId,
      line.map((each) => each.standing),
    )
    const entrant = { player, name, standing }
    line.push(entrant)
    return entrant
  },
  leave: (entrant) => {
    line = line.filter((each) => each !== entrant)
  },
})
```

## The next match

`nextMatch(line, size, standing)` picks two sides of `size` players. It takes
the `2 * size` players who have played the fewest matches, the earlier in
line first among equals. It deals them by rating in a snake: first, second,
second, first. This keeps the sides' ratings close. With one per side, the
two players pair off. With two per side, the best pairs with the worst
against the middle two. While too few players wait, `nextMatch` returns
nothing; the HUD shows that state as waiting for players.

```ts
const sides = nextMatch(line, size, (each) => each.standing)
if (sides) {
  for (const fighter of sides.flat()) {
    fighter.standing.played++
  }
}
```

Count the match as played when it is seated, not when it ends, so a fighter
who leaves mid-match still goes to the back of the order.

## The result

`settle(winners, losers)` records a finished match. Both sides' ratings move
by the Elo step between their average ratings, larger for an upset. The
wins, losses, and streaks count it. It returns the change, for a banner such
as `+16`.

`ratingChange` returns the same step alone. Both calls take a `step` other
than `ratingStep` (32) for a mode whose matches should count more or less.

`afterMatch(line, fought)` sends the fighters to the back of the line.
Everyone else keeps their order ahead of them.

```ts
const change = settle(
  winners.map((each) => each.standing),
  losers.map((each) => each.standing),
)
line = afterMatch(line, [...winners, ...losers])
```

## An even share of heroes

When the mode chooses each fighter's hero from a short list, count the
matches each player has played as each. `leastUsed(counts, prefer)` returns
the one they have played least, or `prefer` when it ties. Everyone plays
every hero about equally. Two fighters can still start on different heroes
by preferring different ones.

```ts
const choice = leastUsed(fighter.standing.heroes, side === 0 ? 0 : 1)
fighter.standing.heroes[choice]++
```

## The leaderboard

`leaderboard(players, standing, rows, viewer)` ranks players by wins and then
rating, and returns the first `rows`. When the viewer would fall off the end,
it keeps them on the last row, so everyone can find themselves. Draw the
board with `Roster`, which shows each row's hero, avatar, and a line of
activity:

```ts
const rows = leaderboard(line, (each) => each.standing, 8, viewer)
show(
  viewer.player,
  Roster({
    rows: rows.map((each) => ({
      name: each.name,
      self: each === viewer,
      hero: each.hero,
      steamId: each.steamId,
      activity: `${each.standing.wins}-${each.standing.losses} · ${each.standing.rating}`,
    })),
  }),
)
```

## The stands

A player waiting for a turn can keep a hero in the world: seated in the
stands, on a hero the fight does not use, watching the ring.
`holdBystander(entity)` keeps the hero out of play. It cannot move, shoot,
cast, or zoom. Abilities from both teams cannot target it. Bullets and melee
pass over it. Displacement cannot pull it out of its seat. It stands beside
the fight without touching it. `holdBystander(entity, false)` gives the hero
back before the player fights.

Teleport the hero to its seat facing the ring, then pin the camera on the
ring with `playCamera`. The `target` param is the point the camera turns
around. A target at the ring's center and a long `distance` give a view the
player circles with the mouse. Each param snaps back when its curve ends.
Keep each curve held for longer than any wait. Clear the context when the
player leaves the stands:

```ts
import {
  type Angles,
  curve,
  holdBystander,
  playCamera,
  type Player,
  type Vector,
} from 'modlock'

const context = 'arena.stands'

function seat(
  player: Player,
  pawn: number,
  position: Vector,
  facing: Angles,
): boolean {
  player.teleport(position, facing)
  holdBystander(pawn)
  player.clearCamera(context)
  const move = playCamera(player, {
    context,
    priority: 4,
    tracks: {
      target: curve.hold({ x: 0, y: 0, z: 60 }, 3600),
      distance: curve.hold(1400, 3600),
      verticalOffset: curve.hold(0, 3600),
      horizontalOffset: curve.hold(0, 3600),
    },
  })
  return move !== undefined
}

function unseat(player: Player, pawn: number): void {
  holdBystander(pawn, false)
  player.clearCamera(context)
}
```

`playCamera` returns nothing while the player has no hero. Mark the seat
taken only once `seat` returns true; try again on the next frame until it
does. A hero dies to falls and world damage like any other. Respawn a
bystander that dies and seat it again.

## Heroes left behind

Swapping a player's hero, or moving them to the spectators and back, can
leave the old hero in the world with nobody driving it. The game then
revives the hero on its own respawn timer. Keep one `Strays` and call
`sweep(now)` each frame. Once a hero has belonged to no player for
`strayGraceSeconds`, the sweep kills it once and holds off its respawn for
good. A hero belongs to a player while its controller points to it, so a
player who is joining or spectating keeps theirs. The sweep looks once a
second, and costs one entity listing and two field reads per hero per
second.

```ts
import { onFrame, Strays } from 'modlock'

const strays = new Strays()
onFrame(({ timeSeconds }) => strays.sweep(timeSeconds))
```

The sweep leaves a stray's abilities in place. Killing the ability entities
of a live hero pawn has ended the server process.

---
title: The framework
description: The parts Modlock is made of.
---

The WebAssembly host is built on Modlock's C++ framework, and
[native plugins](/internals/native-plugins) are built on the same framework.
It has these parts:

- **Plugin host.** `modlock-host` runs a dedicated server, and loads mods and
  plugins into it.
- **Engine events.** `EngineHost` delivers frames, chat, commands, damage,
  connections, respawns and worlds to the mods and plugins.
- **Entities and rendering.** The framework draws world text, particles and
  effects, controls player pawns and bots, and traces rays.
- **Engine interop.** The framework scans for byte signatures, hooks vtables,
  reads schema offsets and builds `CEntityKeyValues`. Every byte signature
  lives in one table, and `modlock-sigcheck` checks that table against the game
  binaries.
- **Session content.** The framework precaches heroes and resources, and
  advertises content addons to the clients that connect.
- **Protocols.** The framework defines Protobuf messages for mods, HUD text,
  chat and camera paths, and generates their code in C++, Go, TypeScript, Luau
  and Python.
- **Portable tests.** The parsing, dispatch, sandbox and fixture tests run on
  macOS and Linux without the game.

The framework runs inside the game's Windows x64 server, either on Windows or
under Proton.

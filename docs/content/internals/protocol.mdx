---
title: How mods reach the game
description: The protocol between a mod and the server that runs it.
---

A mod is a WASI preview 1 reactor module. It imports two functions and exports
one:

| Name                                 | Direction   | Meaning                                                                                                                                                                                         |
| ------------------------------------ | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `modlock.host_call(ptr, len) -> len` | mod to host | Hand the host an encoded `Call`; returns the length of the encoded `Reply`.                                                                                                                     |
| `modlock.host_read(ptr, len)`        | mod to host | Copy the host's pending message, a `Call` or a `Reply`, into mod memory.                                                                                                                        |
| `modlock_event(len) -> i64`          | host to mod | Deliver a `Call` of `len` bytes, which the mod copies with `host_read`. Returns the address and length of the encoded `Reply`, packed as `address << 32 \| length`, or zero for an empty reply. |

Take one server frame in which the mod sends a player a chat line. Here is each
step:

1. The host encodes a `Call` for the frame event, holds it, and calls
   `modlock_event` with its length.
2. The mod passes a buffer of exactly that length to `host_read`, which copies
   the call into it.
3. The mod's frame handler runs. To send the chat line, the mod encodes the
   request as a `Call` and passes it to `host_call`.
4. The host answers the call at once. It holds the encoded `Reply` and returns
   its length, and the mod copies the reply out with `host_read`, as in step 2.
   The host's time on that call counts against the frame's budget.
5. When the handler returns, `modlock_event` returns the address and length of
   the mod's own `Reply`, and the host decodes that reply from mod memory.

The calls are in
[`src/wasm/wasm.proto`](https://github.com/paralin/modlock/blob/master/src/wasm/wasm.proto).
A `Call` contains an encoded request for one method: mod-to-host calls target
the `Host` service, and host-to-mod events target the `Mod` service. The
`Reply` contains the encoded response or an error. Each new capability is added
as a new method, so the three WASI imports/exports never change. Each event runs
within a CPU time budget to stop runaway loops, and each mod has a memory limit.

A program that embeds the host can add services of its own for mods to call,
such as a service for a game mode's match rules. The program provides a service
with `WasmHost::Provide`. Mods call it with the host's `CallService` method,
which a mod's library spells `callService(service, method, payload)`.

The calls also go the other way. A mod serves a service by registering a handler
with `serve(service, handler)`. The program calls that service with
`WasmHost::Call`, which delivers the mod's `Serve` event to the handler. Each
service defines its methods and the encoding of their payloads. A mod cannot be
called while it is calling the host.

An interpreted mod's built `mod.json` lists a runtime, such as
`RUNTIME_QUICKJS`, in place of a module. The host runs the interpreter module
that comes beside `modlock-host`, and hands it the mod's source in the start
event.

## Message packages

Each concern's messages are in a `.proto` file beside the code that implements
it, in a package of its own named after its directory. For example,
`src/wasm/players/players.proto` declares:

- the protobuf package `modlock.wasm.players`
- the C++ namespace `modlock::wasm::players`
- the Go package `github.com/paralin/modlock/src/wasm/players`

The calls between a mod and the host are in
[`src/wasm/wasm.proto`](https://github.com/paralin/modlock/blob/master/src/wasm/wasm.proto),
and their messages are in the packages beside it. `bun run gen` regenerates all
of the Go, TypeScript, Luau, Python and C++ code with the protobuf toolchain the
repository pins.
[Building Modlock](/internals/building#run-the-command-from-a-clone) explains
where `modlock build` gets the TypeScript library.
